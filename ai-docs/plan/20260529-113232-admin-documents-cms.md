# План: панель управления документами через CMS

## Кратко

Текущий сайт — статический HTML/CSS/JS на GitHub Pages. Для выбранного варианта “CMS через GitHub” оптимально добавить Decap CMS: воспитатель заходит в `/admin/`, загружает/удаляет документы через форму, CMS делает commit в GitHub, GitHub Pages обновляет сайт.

Важное ограничение: Decap CMS с GitHub Pages требует OAuth-аутентификацию. По документации Decap, GitHub backend требует сервер для auth; Netlify часто используется как auth-посредник. Если строго остаёмся на GitHub Pages, нужно подключить внешний OAuth-сервис/сервер авторизации либо рассмотреть Netlify только для авторизации/деплоя.

## Что найдено в проекте

- `index.html` содержит все карточки документов вручную:
  - `#diploms` — дипломы/образование
  - `#education` — сертификаты и отчёты самообразования
  - `#achievements` — награды
  - `#monitoring` — мониторинг
  - `#parents` — материалы для родителей
- `js/site.js` содержит данные мониторинга в `yearData`, включая ссылки на DOCX.
- Документы уже разложены по папкам: `diploms/`, `sertificats/`, `self-education/`, `awards/`, `monitoring/`, `recomendation/`.
- В `CONTINUITY.md` есть ограничение “avoid heavy libraries unless requested”; для админки Decap оправдан, потому что не утяжеляет публичную страницу, а подключается только в `/admin/`.

## Предлагаемая архитектура

1. Вынести списки документов из HTML/JS в отдельные JSON-файлы:
   - `data/diploms.json`
   - `data/certificates.json`
   - `data/self-education.json`
   - `data/awards.json`
   - `data/monitoring.json`
   - `data/recommendations.json`

2. Переписать публичный сайт так, чтобы он рендерил карточки документов из этих JSON-файлов:
   - `index.html`: оставить контейнеры/шаблоны секций.
   - `js/site.js`: добавить загрузку JSON через `fetch`, функции рендера карточек и безопасную обработку пустых списков/ошибок.
   - `css/site.css`: при необходимости добавить стили для состояния “документов пока нет”.

3. Добавить Decap CMS:
   - `admin/index.html` — страница админки с подключением Decap CMS.
   - `admin/config.yml` — описание коллекций и полей.
   - Для каждого раздела сделать удобные поля:
     - название
     - тип документа/категория
     - описание или подпись
     - файл через `widget: file`
     - иконка/эмодзи/цвет карточки
     - порядок отображения
     - флаг “показывать на сайте”

4. Настроить загрузку файлов:
   - Для каждого раздела сохранить текущую структуру папок или использовать единый `uploads/documents`.
   - Лучше сохранить текущие папки, чтобы ссылки и структура остались понятными:
     - дипломы → `diploms/`
     - сертификаты → `sertificats/`
     - самообразование → `self-education/`
     - награды → `awards/`
     - мониторинг → `monitoring/`
     - рекомендации → `recomendation/`
   - Добавить ограничения/подсказки в CMS: PDF/DOCX, понятное имя, без персональных данных детей.

5. Мониторинг:
   - На первом этапе дать возможность добавлять/удалять годы мониторинга и два файла на год.
   - Сохранять также показатели, которые сейчас захардкожены в `yearData`.
   - Рендер кнопок годов динамически из `data/monitoring.json`.

6. Аутентификация и публикация:
   - Вариант A, если остаёмся на GitHub Pages: настроить GitHub OAuth для Decap через внешний auth-сервис.
   - Вариант B, проще в эксплуатации: перенести публикацию на Netlify или использовать Netlify Identity/Git Gateway; сайт всё равно останется статическим.
   - Пользователю-воспитателю нужен GitHub-аккаунт с доступом к репозиторию либо отдельная auth-настройка.

## Риски

- GitHub Pages сам по себе не решает OAuth для Decap CMS; нужен внешний auth-механизм.
- Если файлов станет много и они будут тяжёлыми, репозиторий может быстро разрастись.
- Удаление документа из списка в CMS может не всегда физически удалить файл из репозитория — это нужно отдельно проверить в выбранной конфигурации.
- DOCX/PDF с персональными данными детей нужно проверять перед публикацией.
- `fetch` JSON на локальном открытии через `file://` может не работать; тестировать лучше через локальный сервер или GitHub Pages.

## Примечания по внешней документации

- Context7 был недоступен из-за ошибки API key, поэтому детали Decap CMS проверены через официальную документацию Decap CMS.
- Decap CMS хранит контент в Git-репозитории и позволяет редактору работать через UI без ручной работы с Git.
- Для GitHub backend пользователи должны иметь push-доступ к репозиторию; GitHub authentication требует сервер/OAuth-посредник.
- Для загрузки документов подходит Decap `file` widget; для редактируемых списков — `list` widget.
